# Постоянное хранилище медиа

Render стирает локальный диск при каждом деплое/перезапуске. Поэтому файлы (фото, видео, кружки, голосовые, документы, стикеры)
хранятся во внешнем объектном хранилище, а в PostgreSQL (таблица `Media`) лежат только метаданные и ссылка.

Приоритет выбора драйвера (по заданным переменным): **Cloudinary → S3/Supabase → диск**.

## Вариант 1 — Cloudinary (основной)
1. Зарегистрируйтесь на cloudinary.com → Dashboard → «Product Environment Credentials».
2. В Render → Environment добавьте: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`. Секрет только на сервере.
3. Деплой. В логах не должно быть предупреждения «Файлы хранятся на диске сервера».
Как это работает: сервер получает файл от клиента, проверяет тип/размер, подписывает запрос (SHA-1, секрет в запрос не попадает) и
загружает в Cloudinary как `raw` (те же байты, без перекодирования); имя файла = `uuid.расширение`. Ошибки 5xx/сеть — до 3 попыток;
лимит тарифа → клиент получает `too_large`; недоступность → `storage_unavailable` (502). Удаление файла вызывает `destroy` в Cloudinary.
Доступ к файлу проверяется на каждый запрос; одноразовые и защищённые медиа отдаются только через сервер (без редиректа на публичную ссылку).
**Лимит размера** зависит от тарифа Cloudinary (на бесплатном для raw-файлов — 10 МБ). Серверные лимиты Mchat (`MEDIA_RULES`) могут быть выше:
для больших видео выберите платный тариф или S3-вариант.

## Вариант 2 — Supabase Storage (S3-совместимый)
1. Supabase → Storage → создайте **публичный** bucket (например `mchat-media`).
2. Storage → S3 Connection: включите S3, создайте ключи.
3. Env: `S3_BUCKET`, `S3_ENDPOINT` (`https://<project>.supabase.co/storage/v1/s3`), `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
   `S3_PUBLIC_URL` (`https://<project>.supabase.co/storage/v1/object/public/<bucket>`).

## Локальная разработка
Без облачных переменных работает диск: `UPLOAD_DIR=./uploads`. Чтобы проверить облако локально — задайте те же `CLOUDINARY_*` в `.env`.

## Перенос ранее загруженных файлов
Файлы, которые ещё лежат на диске, переносятся скриптом (пока диск жив — до следующего деплоя; на Render запускайте в Shell сервиса):
```bash
npx tsx scripts/migrate-media-to-cloud.ts           # пробный прогон, ничего не меняет
npx tsx scripts/migrate-media-to-cloud.ts --apply   # загрузить и записать url в БД
```
Файлы, которых на диске уже нет (потеряны прошлыми деплоями), восстановить нельзя — скрипт сообщит их количество.

## Проверка сохранности после перезапуска
1. Отправьте фото/голосовое/кружок. В панели Cloudinary → Media Library → Raw появится файл `uuid.ext`.
2. Render → Manual Deploy → «Clear build cache & deploy» (или Restart).
3. Откройте тот же чат: медиа на месте. Админ: в логах старта `checkMediaIntegrity` не должно быть «файлы пропали».
