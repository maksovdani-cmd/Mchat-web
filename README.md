# Mchat — бэкенд

Node.js + Express + TypeScript · PostgreSQL + Prisma · Socket.IO (WSS) · Web Push · вход через Google.
Фронтенд (твои `index.html` / `style.css` / `script.js`) лежит в `public/` и отдаётся этим же сервером —
поэтому cookie, сокеты и API работают с одного адреса без CORS-проблем.

## Как работает вход

```
Ввёл ник ──► «Войти через Google» ──► выбрал аккаунт
                                         │
              ┌──────────────────────────┴───────────────────────────┐
     аккаунта ещё нет                                        аккаунт уже есть
              │                                                       │
   создаём профиль с ником                       это устройство уже известно серверу?
   → СРАЗУ внутрь (кода нет)                       ├─ да  → сразу внутрь (кода нет)
                                                   └─ нет → 6-значный КОД
                                                            ├─ приходит на уже вошедшие устройства
                                                            │  (мгновенно по сокету + push, как в Telegram)
                                                            └─ если доставить некуда → на email из Google
```

* Ник вводится только при регистрации; у существующего аккаунта он игнорируется.
* После верного кода устройство становится доверенным на 1 год — повторно код не просят.
* Сессия — JWT в `httpOnly + Secure + SameSite=Lax` cookie (JS страницы её прочитать не может).
  Каждая сессия записана в БД, поэтому её можно отозвать мгновенно (выход, «удалить устройство»).

## Быстрый старт (на своём компьютере)

```bash
npm install
cp .env.example .env            # заполни (см. ниже)
docker run -d --name mchat-db -e POSTGRES_USER=mchat -e POSTGRES_PASSWORD=mchat \
  -e POSTGRES_DB=mchat -p 5432:5432 postgres:16-alpine
npm run secret                  # вставь результат в JWT_SECRET
npm run vapid                   # вставь ключи в VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY
npm run db:push                 # создать таблицы
npm run dev                     # http://localhost:3000
```

Положи в `public/img/`: свой `mchat.jpg`, а также `icon-192.png` и `icon-512.png` (иконки PWA и пушей).

### Google OAuth (5 минут)
1. https://console.cloud.google.com → создай проект → **APIs & Services → OAuth consent screen** (External, заполни название и email).
2. **Credentials → Create credentials → OAuth client ID → Web application**.
3. **Authorized redirect URIs**: `http://localhost:3000/api/auth/google/callback` (и для продакшена `https://ТВОЙ-ДОМЕН/api/auth/google/callback`).
4. `Client ID` и `Client secret` → в `.env` (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`).

### Почта (нужна только для запасного кода «на почту»)
Любой SMTP: Resend, Brevo, Mailgun, Gmail (пароль приложения). Без SMTP в dev код печатается в консоль сервера.

## Деплой на VPS (HTTPS + WSS автоматически)

Нужен сервер с Docker и домен, направленный на его IP.

```bash
cp .env.example .env
# заполни: APP_URL=https://твой-домен, DOMAIN=твой-домен, DB_PASSWORD, JWT_SECRET, GOOGLE_*, VAPID_*
docker compose up -d --build
```
Caddy сам получит сертификат Let's Encrypt и проксирует и HTTPS, и WebSocket (это и есть WSS).
Приложение в production откажется запускаться, если `APP_URL` не `https://`.

## Что где лежит

| Путь | Назначение |
|---|---|
| `src/routes/auth.ts` | Google OAuth (state + nonce + PKCE), коды нового устройства, выход |
| `src/routes/chats.ts` | список чатов, «Написать», история, отправка (REST-запасной путь), прочитано |
| `src/routes/users.ts` | `/me`, поиск, профиль, устройства, удаление аккаунта |
| `src/routes/push.ts` | подписка/отписка Web Push |
| `src/realtime/socket.ts` | Socket.IO: `message:send`, `chat:read`, `typing`, presence |
| `src/services/chat.ts` | **проверка членства в чате** (`assertMember`) — на каждом запросе |
| `public/mchat-api.js` | все `fetch()` и `socket.emit()` фронтенда в одном файле |
| `public/sw.js` | Service Worker: показывает push, открывает чат по клику |
| `prisma/schema.prisma` | схема БД |

## Безопасность — что и чем закрыто

| Угроза | Защита |
|---|---|
| Чужой читает переписку | Каждый REST-запрос и каждое socket-событие проверяют, что ты участник чата; не участник получает 404. Сокет-комнатами управляет только сервер |
| Кража сессии через XSS | JWT в `httpOnly` cookie; весь текст с сервера экранируется перед выводом (`esc()` в `script.js`) |
| Подделка запросов с чужого сайта (CSRF) | `SameSite=Lax` + проверка `Origin` на всех изменяющих запросах; `state`+PKCE в OAuth |
| Чужой сайт открывает сокет от твоего имени | Проверка `Origin` при подключении сокета |
| Перебор кода входа | 6 цифр, 10 минут, 5 попыток на код (счётчик атомарный), одноразовый, в БД только HMAC-хэш, лимит запросов по IP |
| Отозванная/украденная сессия | Сессия проверяется по БД на каждом запросе и при подключении сокета; выход/отзыв устройства рвёт живые сокеты |
| Спам | Лимиты: общий по IP, вход, коды, поиск, 20 сообщений/10 сек на пользователя |
| Дубли при плохой сети | `clientId` — повторная отправка не создаёт второе сообщение |
| SSRF через push-подписку | принимаются только адреса настоящих push-сервисов (FCM, Mozilla, Apple, Windows) по HTTPS |
| Подмена ника официальных аккаунтов | зарезервированные ники (`admin`, `mchat`, `support`…) |
| Нет HTTPS/WSS | в production сервер требует `https://`, редиректит http→https, включает HSTS |

## Что нужно знать (честно)

* **Сообщения не сквозное шифрованные (не E2EE).** Трафик защищён TLS, доступ ограничен участниками, но сервер технически
  может прочитать текст. Полноценное E2EE — отдельный большой проект.
* **Пока на сервере: вход, профиль (имя, био), чаты, сообщения, presence, push, устройства.**
  Посты, сторис, лайки, подписки, загрузка аватаров/баннеров/видео и админ-панель верификации в `script.js`
  по-прежнему работают на `localStorage` — это следующие этапы. Как только посты переедут на сервер, весь их текст
  тоже нужно выводить через `esc()`.
* **Схема БД создаётся через `prisma db push`.** Когда в базе появятся реальные данные — перейди на
  `npx prisma migrate dev` и `npm run db:deploy`.
* **Один сервер.** «Кто онлайн» хранится в памяти процесса. Для нескольких инстансов добавь Redis-адаптер Socket.IO.
* **CSP разрешает `'unsafe-inline'`**, потому что в вёрстке много `onclick="…"`. Если когда-нибудь переведёшь их на
  `addEventListener`, эту строку в `src/server.ts` можно убрать — защита от XSS станет заметно сильнее.
* **Кнопка «код на почту»** — запасной путь на случай потери всех устройств. Но если кто-то взломал сам Google-аккаунт,
  он получит и письмо. Хочешь строже — `ALLOW_EMAIL_FALLBACK=false` (тогда код приходит только на твои вошедшие устройства;
  если их нет, письмо всё равно уйдёт, чтобы не заблокировать тебя навсегда).
* В `nameChangedAt` (ограничение «имя раз в 7 дней») остаётся на клиенте — сервер этого пока не проверяет.
